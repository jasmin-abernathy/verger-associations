# Cas d’usage

## Lire ce document

Chaque scénario indique la brique principale à utiliser. La règle générale est simple : la conversation reste dans Delta Chat, l’interaction structurée dans Webxdc, l’automatisation dans un robot et les données officielles dans le back-office.

## Réunion d’un conseil d’administration

**Besoin :** préparer une réunion, partager l’ordre du jour, examiner les propositions et conserver les suites.

- groupe Delta Chat pour les échanges ;
- mini-app « Réunions et décisions » pour l’ordre du jour, les propositions et les actions ;
- export du relevé après validation ;
- dépôt du procès-verbal définitif dans le stockage documentaire officiel.

## Organisation d’un événement

**Besoin :** trouver une date, répartir les rôles et rappeler les échéances.

- mini-app Webxdc pour les disponibilités et les rôles ;
- canal Delta Chat pour les annonces ;
- robot facultatif pour les rappels issus du calendrier officiel ;
- inscription publique sur le site si des personnes extérieures participent.

## Mobilisation de bénévoles

**Besoin :** publier des besoins concrets sans imposer un nouvel outil de gestion.

- canal pour annoncer les besoins ;
- mini-app pour se positionner volontairement ;
- export limité aux informations utiles aux coordinateurs ;
- aucune constitution automatique d’un profil détaillé des bénévoles.

## Accueil d’un nouveau membre

**Besoin :** fournir les informations essentielles sans perdre la personne dans plusieurs plateformes.

- invitation dans les groupes nécessaires uniquement ;
- mini-app d’accueil avec étapes, documents et contacts ;
- Hitobito pour l’adhésion, les rôles et les consentements officiels ;
- validation humaine de la fin du parcours.

## Consultation interne

**Besoin :** recueillir un avis auprès d’un groupe identifié.

- mini-app de questionnaire ;
- réponses nominatives ou anonymisées selon une décision préalable ;
- synthèse exportable ;
- pas de promesse d’anonymat si l’architecture ne permet pas de le garantir.

## Entraide locale

**Besoin :** publier une demande ou une proposition d’aide dans un cercle de confiance.

- groupe limité aux personnes concernées ;
- mini-app pour catégoriser, attribuer et clôturer ;
- suppression ou archivage maîtrisé après résolution ;
- pas de publication automatique sur un annuaire public.

## Alertes réglementaires ou thématiques

**Besoin :** transformer une veille en action associative.

- `alerts.lepotager.org` détecte et qualifie la nouveauté ;
- un robot publie une alerte résumée dans le bon groupe ;
- les membres indiquent « pertinent », « à étudier » ou « ignorer » ;
- une action et un responsable peuvent être créés.

## SCOP ou SCIC

**Besoin :** coordonner des cercles de travail sans multiplier les plateformes.

- groupes par cercle ou projet ;
- canaux pour les annonces transversales ;
- mini-apps pour décisions, réunions et actions ;
- outil de gestion dédié pour comptabilité, paie, sociétariat et documents légaux.

## Situations où Webxdc n’est pas le bon outil

- comptabilité et facturation ;
- stockage exclusif des procès-verbaux définitifs ;
- base centrale de membres ;
- traitement complexe exigeant une connexion permanente à plusieurs API ;
- publication destinée au grand public ;
- urgence vitale ou système exigeant une garantie stricte de livraison.
